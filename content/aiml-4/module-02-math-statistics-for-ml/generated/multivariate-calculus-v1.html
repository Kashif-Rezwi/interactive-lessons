UNIT 1 · WHY CALCULUS IN ML

Every model is a machine with dials

CLASS CORE Machine learning fundamentally solves optimization problems: a model learns by minimizing error. Whatever the system — a classifier, a regressor, a generator — training means repeatedly adjusting the model's parameters (its dials: weights and biases) until a number that measures wrongness, the loss function, is as small as we can make it. The source names the usual loss families: classification loss, regression loss, cross-entropy loss (for comparing probability distributions), reconstruction loss (how badly an autoencoder rebuilds its input). source

FOUNDATION To make "minimizing error" concrete, this lesson uses the simplest regression loss, mean squared error (MSE) — the one the source's linear-regression example assumes but never writes down:

L(w, b) = (1/n) · Σᵢ (ŷᵢ − yᵢ)²   where ŷᵢ = w·xᵢ + b
  • w, b — the two parameters (dials): slope and intercept of the line we fit
  • xᵢ, yᵢ — the i-th data point: input and true answer
  • ŷᵢ — the model's prediction for xᵢ
  • n — how many data points we average over
  • Why it makes sense: each point contributes the square of its miss; the loss is the average miss-squared, so big misses are punished disproportionately and misses above and below the line don't cancel. How to read the result: 0 means a perfect line; smaller is always better.

Worked by hand before any buttons: one point (x, y) = (1, 3), model ŷ = 2x. The prediction is ŷ = 2, the error is 2 − 3 = −1, the squared error is 1, and with n = 1 the MSE is 1. One dial (w = 2), one number that says how wrong it is. constructed example

UNIT 2 · PARTIALS & THE GRADIENT

A partial is the slope of one dial, all others frozen

CLASS CORE The loss is a function of many variables — in the explorer above, L(w, b). The first tool for such functions is the partial derivative: the rate of change with respect to one variable while keeping all the others fixed. source

∂f/∂x — "the slope of f along x, with every other variable frozen"
  • ∂ — the rounded d signals a partial derivative: a plain derivative, but taken in a world where only one variable is allowed to move
  • f — the function whose change we are measuring (later: the loss L)
  • x — the one variable that moves; everything else is held constant
  • Why it makes sense: "how fast does f change if I nudge only x" is exactly the one-dial question a trainer needs to ask about every parameter. How to read the result: a positive value means f rises as x grows; 0 means f is momentarily flat along x.

CLASS CORE The source's worked example, recomputed live: for f(x, y) = x² + 3y, the partial with respect to x treats y as a constant — the 3y term contributes nothing to change — so ∂f/∂x = 2x; the partial with respect to y treats x as a constant, so ∂f/∂y = 3. At the point (x, y) = (2, 4): ∂f/∂x = 4 and ∂f/∂y = 3 — the same two numbers the source's code cell prints. source

f(x,y) = x² + 3y  ⇒  ∂f/∂x = 2x,   ∂f/∂y = 3
  • x² — changes with x, so it survives ∂/∂x as 2x; it is a constant from y's point of view, so it vanishes from ∂f/∂y
  • 3y — a wall from x's point of view (vanishes from ∂f/∂x); from y's point of view it is a straight ramp of slope 3
  • How to read the result at (2,4): nudging x by +0.01 raises f by about 4·0.01; nudging y by +0.01 raises f by 3·0.01. The x-dial currently matters more.

CLASS CORE The source's picture: imagine standing on a mountainside. You can move east-west or north-south, and each direction has its own slope. A partial derivative measures the slope along the one direction you chose, with the other frozen. In ML the mountain is the loss surface: for a model with parameters w₁, …, w_m, the partial ∂L/∂wᵢ measures the sensitivity of the loss to parameter i — a large partial means that parameter strongly affects the loss right here; a small one means its local effect is weak. source

CLASS CORE One slope per dial invites the obvious next move: stack all the slopes into a vector. That vector is the gradient, the single most important object in this lesson. source

∇f = [ ∂f/∂x, ∂f/∂y, … ]    e.g. ∇f(2,4) = [4, 3] for f = x² + 3y
  • ∇ — "nabla": the operator that collects all partials into a vector, one entry per variable
  • each entry ∂f/∂xᵢ — the slope of f along axis i alone
  • Why it makes sense: a direction in the parameter space needs one coordinate per axis; the gradient provides exactly one slope per axis. How to read the result: an arrow whose entries say how f responds to each dial — not a single number.

CLASS CORE Two more facts from the source, both earned live below: the magnitude ‖∇f‖ measures how steep the surface is at your feet — large magnitude means steep slope, small magnitude means a flat region — and the gradient points in the direction of steepest increase. Flip its sign and −∇f points in the direction of fastest descent. Why "steepest" is exactly right is Unit 3's theorem-in-waiting; for now treat it as the promise marked on the concept map. source

‖∇f‖ = √( (∂f/∂x)² + (∂f/∂y)² + … )    steepness of the surface at the current point
  • ‖·‖ — the length of the gradient vector (the Class 1 norm, reused)
  • Why it makes sense: it folds every axis's slope into one overall steepness number. How to read the result: ‖∇f‖ = 0 means every direction is (locally) flat — the walk is done or stuck.
Beginner trap. The gradient is not "the biggest partial" and not a single number at all. If a classmate reports "the gradient at (2,4) is 4, because ∂f/∂x is the bigger partial," they have thrown away the y-information: the gradient is the vector [4, 3]. Losing the vector means losing the direction — and direction is the whole point.

DEEP DIVE Walk down instead of up and you get the workhorse of all of ML. The source states the update rule; the lab below makes every piece of it draggable:

θ := θ − η · ∇f(θ)
  • θ — the current parameters (all dials at once, as a vector)
  • ∇f(θ) — the gradient measured at the current setting: the uphill arrow
  • η (eta) — the learning rate: a small positive step size controlling how far to walk
  • − — the sign flip: subtract the uphill direction and you walk downhill
  • := — "becomes": repeat this update over and over. Why it makes sense: each dial moves against its own slope, proportionally to it. How to read the result: the sequence of θ's is the training trajectory of gradient descent.

CLASS CORE The source's own numbers, live: start at x = 5 on f(x) = x² (so ∇f = 2x = 10), set η = 0.1, and iterate. Each step multiplies x by 1 − 2η = 0.8, so after 20 steps x = 5 · 0.8²⁰ ≈ 0.0576 — the descent works, and it slows down as it approaches the flat bottom, where the gradient (and hence the step) shrinks. source (recomputed live below)

UNIT 3 · DIRECTIONAL DERIVATIVES

Any direction's climb rate is a projection

CLASS CORE Partials answer "how fast does f change along an axis?" The directional derivative answers the general question: "how fast does f change if I move in THIS direction?" — any direction, not just the axes. source

Duf = ∇f · u    (u a unit vector)
  • u — the chosen direction, scaled to length 1 so the answer means "rate per unit of step"
  • ∇f — the gradient at the point you are standing on
  • · — the Class 1 dot product: multiply matching coordinates and add
  • Why it makes sense: the dot product reads off the part of ∇f that points along u — the projection of the gradient onto your direction. Only the slope along your walk matters to how fast you climb. How to read the result: positive = uphill along u; negative = downhill; 0 = flat to first order.

supplemental Now the proof Unit 2 promised. Write the angle between u and ∇f as φ. The dot product of a unit vector with anything is that thing's projection, and the projection of ∇f onto u has length ‖∇f‖·cos φ:

Duf = ‖∇f‖ · cos φ ≤ ‖∇f‖    with equality exactly when φ = 0
  • φ — the angle between your direction u and the gradient
  • cos φ — the fraction of the gradient's steepness your direction captures: 1 when aligned, 0 when perpendicular, negative when walking against it
  • Why it makes sense: cos φ ≤ 1, so no direction can climb faster than ‖∇f‖, and the only direction that achieves the maximum is u = ∇f/‖∇f‖ — the gradient direction. That is the steepest-ascent property, now earned instead of asserted. How to read the result: perpendicular to the gradient, cos φ = 0: the surface is flat to first order along that line.

CLASS CORE The source's worked example, used live below: at a point where ∇f = [3, 4], the magnitude is √(3² + 4²) = 5, so the maximum possible directional derivative is 5, achieved along the unit direction (3, 4)/5. Any other unit direction scores strictly less. source

Beginner trap. "The maximum of ∇f·u is 25, achieved at u = (3, 4)." No — u must be a unit vector: the question is "per unit of step." Feeding the unnormalized (3, 4) gives 3·3 + 4·4 = 25, but that is the climb rate for a walk of length 5, not length 1. Normalize first: u = (3, 4)/5, and the honest maximum is 5.

UNIT 4 · THE CHAIN RULE (CRITICAL)

Gradients flow backward by multiplying local slopes

CLASS CORE Deep learning systems are nested compositions of functions: input → layer 1 → activation → layer 2 → … → output → loss. To train such a tower, the loss's sensitivity must reach every parameter, including the ones buried in early layers — gradients must flow backward through the composition. The tool that makes that possible is the chain rule. The source marks it CRITICAL, and means it: without the chain rule, deep learning cannot exist. source

CLASS CORE source (formula corrected) One honest note before the mathematics: the source notebook's printed formula reads "dy/dg = dg/dx", which equates two unrelated derivatives — a transcription slip, confirmed as such by the source's own code cell, which correctly multiplies the two local derivatives. The intended statement, standard in every calculus text, is:

y = f(g(x))  ⇒  dy/dx = (dy/dg) · (dg/dx)
  • g(x) — the inner function: its output feeds the next stage
  • f — the outer function: it consumes g's output
  • dy/dg — the outer stage's local slope: how y responds to its input
  • dg/dx — the inner stage's local slope: how that input responds to x
  • Why it makes sense: a small nudge to x gets scaled by the inner slope, then that scaled nudge gets scaled again by the outer slope — effects through a pipeline multiply. How to read the result: the total sensitivity of the far end to the near end is the product of local sensitivities along the path.

CLASS CORE The source's worked numbers, live below: take g = x² and y = g + 1, evaluated at x = 2. Forward: g = 4, then y = 5. Backward: dg/dx = 2x = 4 and dy/dg = 1, so dy/dx = 1 · 4 = 4 — exactly what the source's code prints. source

CLASS CORE For functions of many variables the rule generalizes the only way it can — every path from the input to the output contributes a product, and the contributions add:

∂L/∂x = Σⱼ (∂L/∂uⱼ) · (∂uⱼ/∂x)
  • L — the loss at the far end of the composition
  • uⱼ — the intermediate quantities x feeds into (the layer outputs)
  • ∂L/∂uⱼ — how the loss responds to intermediate j (already computed when working backward)
  • ∂uⱼ/∂x — how intermediate j responds to x (a local slope)
  • Why it makes sense: influence flows along every path; sum the per-path products. How to read the result: one entry of the gradient the trainer needs for dial x.

CLASS CORE The bookkeeping structure is the computational graph: nodes hold quantities, edges hold the local derivatives. The forward pass computes values left-to-right until the loss exists; the backward pass walks the same edges right-to-left, multiplying and summing local derivatives. Applied to a neural network layer by layer, this is backpropagation: repeated chain rule, organized by a graph. source

Beginner trap. "Backpropagation is a clever algorithm separate from calculus." It is not a new law — it is the chain rule applied systematically: one product per path, one local derivative per node, reused for every parameter that path touches. The engineering feat is bookkeeping efficiency, not new mathematics.

Model answer (grade yourself honestly): each layer composes functions, so the loss is one long composition y = f(…g(x)). The chain rule says the derivative of a composition is the product of local derivatives along the path; a network merely has many paths, so the total gradient sums one product per path. The graph contributes the bookkeeping: it stores each node's local derivative once and reuses it for every parameter downstream, and it fixes the order (backward pass) in which products and sums are assembled. New organization — no new calculus.

UNIT 5 · JACOBIAN, HESSIAN & CURVATURE

First order says direction; second order says shape

CLASS CORE The gradient handles functions with many inputs and one output. But a neural-network layer maps its input to many outputs — a vector-valued function F(x) = [f₁(x), …, f_m(x)]. Its derivative is not one vector but a whole matrix of them: the Jacobian, one row per output, one column per input. source

Jij = ∂fi/∂xj    shape: (number of outputs) × (number of inputs)
  • fi — the i-th output of the function
  • xj — the j-th input coordinate
  • Jij — the sensitivity of output i to input j
  • Why it makes sense: each output deserves its own gradient; stacking those gradients as rows gives the complete first-order picture. How to read the result: the best linear approximation of the transformation near the point — its entries describe local stretching, scaling, and rotation. A function with 3 outputs from 2 inputs has a 3×2 Jacobian.

CLASS CORE The source's example matrix, live: J = [ 2 1 ][ 0 3 ] transforms any input v = (v₁, v₂) into J·v = (2v₁ + v₂, 3v₂) — stretching, shearing, and rotating its neighborhood. Feed it a vector mentally: (1, 1) ↦ (3, 3). The source names where this machinery runs: backpropagation itself, vector transformations, normalizing flows (invertible models built from exactly these local maps), diffusion models (which push data through such transformations while adding noise), and sensitivity analysis (how much each input moves each output). source (applications glossed)

CLASS CORE Now zoom out one order of derivatives. The Hessian collects the second-order derivatives — the derivatives of the gradient's entries. Where the gradient gave the tilt of the surface, the Hessian gives its curvature: how the slope itself bends. source

Hij = ∂²f/∂xi∂xj    — "differentiate the gradient once more"
  • ∂²f/∂xi∂xj — first differentiate with respect to xj, then with respect to xi
  • diagonal entries ∂²f/∂xᵢ² — the curvature along each pure axis: is the axis-slope itself rising or falling?
  • Why it makes sense: gradient = first-order local model (a tilted plane); Hessian = second-order local model (how the plane itself bends). For smooth functions the mixed entries come out equal, so H is a symmetric matrix — the shape the Class 2 eigenvalue machinery applies to.

FOUNDATION Why curvature classifies critical points — the second-order view the source assumes. Near any setting θ, a smooth loss behaves like:

f(θ + δ) ≈ f(θ) + ∇f(θ)·δ + ½·δᵀ H δ
  • δ — a small step away from θ
  • ∇f(θ)·δ — the first-order tilt: 0 exactly at a critical point, where ∇f = 0
  • ½·δᵀHδ — the curvature term: what remains when the tilt vanishes — it alone decides whether the critical point is a floor, a ceiling, or a horse's back
  • How to read the result: at a critical point, walk in each eigen-direction of H (Class 2): if every eigenvalue is positive the surface bends up in all directions — a positive definite Hessian and a local minimum (a valley). All negative: negative definite, a local maximum (a peak). Mixed signs: indefinite, a saddle point — up in some directions, down in others.

CLASS CORE The source's summary table, tightened to per-direction truth: positive curvature = bowl-shaped, negative = dome-shaped, mixed = saddle. And its warning: deep-learning landscapes are packed with saddle points and flat plateaus, which is precisely why optimization there is hard. source (direction-dependence tightened)

Beginner trap. "∇f = 0, so we found a minimum." A zero gradient only says: flat in every direction to first order. The Hessian then decides the fate: all-positive eigenvalues → minimum; all-negative → maximum; mixed signs → saddle — a point that is a minimum along some directions and a maximum along others. In high-dimensional losses saddles vastly outnumber true minima, so "∇f = 0" is usually the beginning of the story, not the end.

  • H⁻¹ — the inverse Hessian: exists only when no eigenvalue is zero (a saddle with a zero eigen-direction, or a flat direction, leaves it undefined — the guard the source omits)
  • ∇f(θ) — the gradient: the direction
  • Why it makes sense: gradient descent takes a fixed-size step and re-measures; Newton divides the slope by the curvature, so steep-but-gently-curving regions get long steps and sharp bowls get short, precise ones. How to read the result: for a quadratic surface, one Newton step lands exactly on the critical point — verify it in the lab's readout. The catch: computing and inverting H for a billion parameters is exactly the cost that keeps deep learning on first-order methods (Unit 6).

UNIT 6 · THE DEEP-LEARNING VIEW

Repeat the chain rule 100 times

CLASS CORE Everything so far ran on toy surfaces. Real deep networks have billions of parameters and highly non-convex landscapes — mountains, valleys, and long stretches where nothing much happens. Multivariate calculus is central to all of it: training stability, optimization, and convergence all live on the machinery you just built. source

CLASS CORE The source's first deep-net warning is pure Unit 4 arithmetic. Backpropagation multiplies one local derivative per layer along the whole path. If each layer's factor is a number λ, a signal crossing k layers arrives multiplied by:

gk = λᵏ    (one factor per layer, multiplied k times)
  • λ — the typical per-layer chain-rule factor: how much that layer scales the gradient passing through it
  • k — the number of layers the gradient must cross
  • Why it makes sense: the chain rule multiplies local slopes; multiplying the same factor k times is exponentiation. λ < 1 shrinks exponentially (a vanishing gradient: early layers learn almost nothing); λ > 1 blows up exponentially (an exploding gradient: updates swamp the weights). How to read the result: 0.9¹⁰⁰ ≈ 0.000027 — a 90%-faithful layer, repeated 100 times, is a disaster.
Beginner trap. "Vanishing gradients happen because something is subtracted at each layer." Nothing is subtracted — the chain rule multiplies. A factor of 0.9 per layer is 0.9·0.9·0.9…, and a hundred of those leave about 0.003% of the signal. Small factors compound; they do not erode linearly.

SYNTHESIS

The walk, end to end

Look back at the concept map — every edge is now earned. Training is optimization: the loss is a surface over the model's dials. Partials give each dial's slope; stacked, they are the gradient, whose projection onto any direction is that direction's climb rate — which is why the gradient is the steepest direction and why walking against it (gradient descent) is the fastest local way down. To reach dials buried in composed layers, derivatives multiply along paths (the chain rule), and applying that rule through the whole computational graph is backpropagation — whose per-layer factors compound into vanishing or exploding gradients. Stack all first-order slopes into a matrix and you have the Jacobian; differentiate once more and the Hessian gives curvature, classifying critical points into minima, maxima, and saddles, and powering Newton's method when the budget allows. GLOSSARY

Every term, six ways

optimization
Simple: making a bad number smaller by choosing well. Precise: the process of searching for inputs that minimize (or maximize) an objective function. Intuition: tuning dials until the needle sits as low as it will go. Example: adjusting w and b until the MSE in Unit 1 hits 0.22. Related: loss function, gradient descent. In practice/ML: training any model is optimization over its parameters.
loss function
Simple: the scoreboard that says how wrong the model is. Precise: a function L of the model's parameters whose value measures prediction error on data. Intuition: the needle the trainer watches. Example: MSE; cross-entropy for classifiers. Related: mean squared error, loss surface. In practice/ML: every framework's loss.backward() starts from one.
parameter
Simple: a dial the training loop is allowed to turn. Precise: a trainable numerical quantity (weight or bias) that the optimizer adjusts; collectively θ. Intuition: one knob among millions. Example: slope w and intercept b in Unit 1's line. Related: parameter space, gradient. In practice/ML: modern networks have millions–billions.
parameter space
Simple: the map of all possible dial settings. Precise: the vector space whose axes are the model's parameters; each point is one complete model configuration. Intuition: every point of the map is a differently-tuned model. Example: the (w, b) plane of Unit 1. Related: high-dimensional, loss surface. In practice/ML: training is a walk through it.
high-dimensional
Simple: having so many coordinates that pictures stop working. Precise: a space whose coordinate count d is large (hundreds to billions). Intuition: the setting where geometry gets strange (Class 3's curse). Example: a 256×256×3 image = 196,608 dimensions. Related: parameter space, non-convex. In practice/ML: all real model training happens here.
loss surface
Simple: the landscape the loss makes over all dial settings. Precise: the graph of L as a function of the parameters — a hypersurface in parameter space plus one loss axis. Intuition: mountains, valleys, slopes, plateaus. Example: Unit 1's MSE bowl over (w, b). Related: loss function, saddle point, plateau. In practice/ML: the terrain every optimizer walks.
mean squared error (MSE)
Simple: the average of the squared misses. Precise: L(w,b) = (1/n)Σ(ŷᵢ−yᵢ)², squared error averaged over data points. Intuition: punish big misses hard; let opposite misses add, not cancel. Example: Unit 1's worked MSE = 1 for the single point (1,3) under ŷ = 2x. Related: loss function. In practice/ML: the default regression loss.
partial derivative
Simple: the slope along one dial with the rest frozen. Precise: the rate of change of f with respect to one variable, all others held constant; written ∂f/∂x. Intuition: east-west slope on the mountain while you promise not to walk north-south. Example: ∂(x²+3y)/∂x = 2x. Related: gradient, sensitivity. In practice/ML: ∂L/∂wᵢ is one entry of the gradient the trainer needs.
gradient
Simple: all the slopes, stacked into one arrow. Precise: the vector ∇f of all first-order partials, one entry per variable. Intuition: the felt uphill direction on a mountain you cannot see. Example: ∇f = (4, 3) at (2,4) for f = x²+3y. Related: partial derivative, gradient magnitude, directional derivative. In practice/ML: the update direction for every parameter, every step.
gradient magnitude (steepness)
Simple: how steep it is where you stand. Precise: ‖∇f‖, the norm of the gradient; the maximum possible rate of increase over all unit directions. Intuition: the arrow's length, not its heading. Example: ‖(3,4)‖ = 5. Related: gradient, directional derivative. In practice/ML: near-zero magnitude is what a plateau feels like.
learning rate
Simple: how big a step to take each update. Precise: the scalar η in θ := θ − η∇f(θ); for a quadratic, stability requires η < 2/λ_max. Intuition: stride length on the mountain — too long and you leap across the valley. Example: Unit 2's descent lab explodes past η = 0.5. Related: gradient descent. In practice/ML: the most-tuned hyperparameter in the field.
gradient descent
Simple: repeatedly step against the uphill arrow. Precise: the iterative update θ := θ − η∇f(θ), descending the loss surface. Intuition: walking downhill by feeling the slope under your feet, one step at a time. Example: x = 5 → ≈0.0576 in twenty steps on f = x² with η = 0.1. Related: learning rate, stochastic gradient. In practice/ML: the engine of essentially all model training.
unit vector
Simple: an arrow of length exactly 1. Precise: u with ‖u‖ = 1; directions are quoted as unit vectors so rates mean "per unit of step." Intuition: a pure direction, with size stripped away. Example: (3,4)/5 = (0.6, 0.8). Related: directional derivative, projection. In practice/ML: normalization (Class 3) makes embedding directions comparable.
directional derivative
Simple: the climb rate along any chosen direction. Precise: Duf = ∇f·u for a unit u; the projection of the gradient onto u. Intuition: how much of the slope works for you on the path you picked. Example: ∇f=(3,4) along (0,1) gives 4. Related: gradient, projection, dot product. In practice/ML: the formal reason "steepest" means the gradient direction.
projection
Simple: the shadow one vector casts on another's direction. Precise: the component of v along u, of length v·u for a unit u. Intuition: how much of v survives if you may only walk along u. Example: Duf = ‖∇f‖cos φ. Related: dot product, directional derivative. In practice/ML: cosine similarity (Class 3) is a projection of directions.
dot product
Simple: multiply matching coordinates and add. Precise: v·u = Σvᵢuᵢ; for a unit u it is the projection of v along u. Intuition: a compatibility score between two arrows. Example: (2,−1)·(1,1)/√2 = 1/√2 ≈ 0.707. Related: projection, directional derivative. In practice/ML: attention (Class 3) is built from dot products.
chain rule
Simple: through a pipeline, slopes multiply. Precise: for y = f(g(x)): dy/dx = (dy/dg)(dg/dx); multivariable: sum one product per path. Intuition: a nudge gets scaled at each stage, and the scalings compound. Example: g = x², y = g+1 at x=2 gives 1·4 = 4. Related: composition, backpropagation. In practice/ML: nothing trains without it.
composition of functions
Simple: functions feeding functions. Precise: y = f(g(x)): the inner function's output is the outer's input. Intuition: an assembly line of stages. Example: input → layer → activation → … → loss. Related: chain rule, computational graph. In practice/ML: a deep network is one long composition.
computational graph
Simple: the wiring diagram of who feeds whom. Precise: a directed graph whose nodes hold quantities and edges hold local derivatives, supporting forward values and backward products. Intuition: the loss's family tree. Example: Unit 4's x → g = x² → y = g+1. Related: chain rule, backpropagation, forward pass. In practice/ML: what PyTorch/TensorFlow/JAX build and differentiate.
forward pass
Simple: push the data through to get the loss. Precise: evaluating the composition left-to-right, recording each node's value. Intuition: doing the work once, keeping the receipts. Example: x=2 → g=4 → y=5. Related: computational graph, backward pass. In practice/ML: one step of inference or one training sample's loss.
backward pass
Simple: walk the receipts back, multiplying slopes. Precise: right-to-left application of the chain rule, reusing stored local derivatives to compute ∂L/∂(every node). Intuition: blame assignment: how much did each dial contribute? Example: dy/dg=1 times dg/dx=4 gives 4. Related: chain rule, backpropagation. In practice/ML: loss.backward() in every framework.
backpropagation
Simple: the chain rule run efficiently through the whole network. Precise: the algorithm that computes the loss's gradient w.r.t. every parameter by one backward pass over the computational graph, reusing each node's local derivative. Intuition: repeated chain rule with smart bookkeeping. Example: the graph lab, scaled to a billion dials. Related: chain rule, computational graph, Jacobian. In practice/ML: the mathematical engine of deep learning.
vector-valued function
Simple: a function with several answers at once. Precise: F(x) = [f₁(x), …, f_m(x)], mapping inputs to m outputs. Intuition: one dial board, many gauges. Example: a layer mapping 2 inputs to 3 outputs. Related: Jacobian. In practice/ML: every network layer is one.
Jacobian
Simple: the gradient of a many-output function, one row per output. Precise: the matrix Jij = ∂fi/∂xj, shape (outputs × inputs); the best linear approximation of the map near a point. Intuition: the layer's local stretch-and-rotate fingerprint. Example: the source's [[2,1],[0,3]]: (1,1) ↦ (3,3). Related: gradient, vector-valued function, Hessian. In practice/ML: backprop, normalizing flows, diffusion, sensitivity analysis.
second-order derivative
Simple: the slope of the slope. Precise: the derivative of a derivative; for multivariable f the entries ∂²f/∂xi∂xj. Intuition: whether the ground is bending up, down, or both. Example: d/dx(2x) = 2 — constant upward bend. Related: Hessian, curvature. In practice/ML: the difference between "flat" and "at the bottom."
curvature
Simple: how the slope itself changes. Precise: the second-order behavior measured by the Hessian; positive = bending up, negative = bending down, mixed = saddle. Intuition: the tilt of the tilt. Example: the curvature lab's two parabola panels. Related: Hessian, saddle point. In practice/ML: why step sizes that work in a gentle bowl fail in a sharp ravine.
Hessian
Simple: the matrix of all second derivatives. Precise: Hij = ∂²f/∂xi∂xj; symmetric for smooth f; classifies critical points via eigenvalue signs. Intuition: the surface's bending profile in every direction. Example: H = diag(3, 5) for the curvature lab's default. Related: Jacobian, eigenvalue, Newton's method. In practice/ML: too big to store for real networks — but its vocabulary is how training is debugged.
eigenvalue
Simple: the stretch factor along one of a matrix's special directions (Class 2's word, reused). Precise: a scalar λ with H·v = λv for some direction v; for a diagonal Hessian the eigenvalues are the diagonal entries. Intuition: the curvature the surface has if you may only walk in that direction. Example: diag(+4, −2): +4 up, −2 down — a saddle. Related: Hessian, positive definite, indefinite. In practice/ML: the 2/λ_max learning-rate threshold in Unit 2.
positive definite
Simple: bends up in every direction — a bowl. Precise: a symmetric matrix all of whose eigenvalues are > 0. Intuition: no escape direction; gravity everywhere points at the middle. Example: diag(3, 5). Related: negative definite, indefinite, local minimum. In practice/ML: the quadratic-approximation test for "did we find a minimum?"
negative definite
Simple: bends down in every direction — a dome. Precise: all eigenvalues < 0. Intuition: a hilltop: every direction loses height. Example: diag(−3, −3) in Unit 5's check. Related: positive definite, local maximum. In practice/ML: rare in loss landscapes, common as local tests.
indefinite
Simple: bends up some ways, down others — a horse's back. Precise: eigenvalues of both signs. Intuition: a mountain pass: ascend or descend depending on your bearing. Example: diag(+4, −2). Related: saddle point. In practice/ML: the dominant critical-point type in high dimensions.
saddle point
Simple: a pass between hills — minimum one way, maximum the other. Precise: a critical point (∇f = 0) with an indefinite Hessian. Intuition: flat underfoot, yet the ground curves both ways. Example: f = −x² + 7y² at the origin. Related: indefinite, critical point, plateau. In practice/ML: deep nets are full of them; training stalls there.
local minimum
Simple: a valley floor — every nearby step goes up. Precise: a point where ∇f = 0 and the Hessian is positive definite (or, weakly, positive semidefinite). Intuition: the bottom of your current bowl, whether or not it is the deepest one. Example: the origin of every bowl in the labs. Related: positive definite, saddle point. In practice/ML: what training converges to — hopefully a deep one.
local maximum
Simple: a hilltop — every nearby step goes down. Precise: a critical point with negative definite Hessian. Intuition: the dome's crown. Example: diag(−3,−3) at the origin. Related: negative definite. In practice/ML: a loss's local maxima are the trainer's dead ends.
critical point
Simple: where the ground is flat in every direction — first order. Precise: a parameter setting where ∇f = 0; its type (min / max / saddle) is decided by the Hessian. Intuition: standing still feels the same on a valley floor, a hilltop, and a pass — curvature tells them apart. Example: the origin in every Unit-5 lab setting. Related: saddle point, local minimum. In practice/ML: "∇L ≈ 0" is how a training run reports being stuck — or done.
Newton's method
Simple: size the step by the curvature, not just the slope. Precise: the update θ := θ − H⁻¹∇f(θ); needs H invertible and a locally good quadratic model. Intuition: a slope of 10 in a sharp bowl deserves a shorter step than a slope of 10 on a valley floor. Example: one step lands the curvature lab's quadratic exactly on its critical point. Related: Hessian, gradient descent. In practice/ML: the H⁻¹ cost is why deep learning stays first-order.
plateau
Simple: a long flat stretch where steps stop helping. Precise: a region where ‖∇f‖ ≈ 0 (to first order flat — e.g. along the gradient's perpendicular), so updates shrink toward zero. Intuition: Unit 3's flat direction, stretched into terrain. Example: λ near 0.5 in the chain-depth lab makes progress crawl. Related: saddle point, adaptive optimizer. In practice/ML: the flat "loss stops moving" phase of real training curves.
non-convex
Simple: a landscape with many valleys, hills, and passes — no single bowl. Precise: a function whose loss surface is not convex; multiple local minima and saddles exist. Intuition: hiking country, not a wok. Example: any deep network's loss. Related: saddle point, loss surface. In practice/ML: the honest description of every real training problem.
vanishing gradient
Simple: the training signal dies before reaching early layers. Precise: repeated chain-rule multiplication by per-layer factors < 1 shrinks the gradient exponentially: λᵏ → 0. Intuition: 0.9 one hundred times is not 90% — it is 0.003%. Example: the chain-depth lab below 10⁻⁴. Related: exploding gradient, chain rule. In practice/ML: the historical obstacle to deep (many-layer) training.
exploding gradient
Simple: the training signal grows until updates wreck the dials. Precise: per-layer factors > 1 compound as λᵏ → ∞. Intuition: the mirror failure of vanishing — a snowball per layer. Example: λ = 1.1, k = 30 → ≈17.4. Related: vanishing gradient, adaptive optimizer. In practice/ML: why training pipelines clamp gradients to a safe range.
adaptive optimizer
Simple: an optimizer that tunes each dial's step size to that dial's history. Precise: a method (Adam, RMSProp, Adagrad) scaling per-parameter updates using gradient statistics, in place of one global η. Intuition: cautious steps on cliffs, confident steps on flats. Example: Adam — the field's default. Related: learning rate, gradient descent. In practice/ML: the standard choice for deep training.
stochastic gradient
Simple: a cheap, slightly random stand-in for the true gradient. Precise: the gradient of the loss on a random mini-batch, used as a noisy estimate of the full-data gradient. Intuition: survey a few voters instead of the country. Example: one batch of 256 samples per update. Related: gradient descent. In practice/ML: how billion-scale training affords millions of updates.
least squares
Simple: the parameter values that make the total squared error as small as possible. Precise: the minimizers of Σ(ŷᵢ−yᵢ)²; for a line, w* = Sxy/Sxx, b* = ȳ − w*x̄. Intuition: the exact best fit the calculus of Unit 2 is walking toward. Example: Unit 1's dataset: w* = 1.7, b* = −0.1, MSE* = 0.22. Related: mean squared error, gradient descent. In practice/ML: closed-form regression; also the textbook test case for optimizers.
residual connection
Simple: a layer design that adds "plus the input unchanged" to its output. Precise: an identity path y = F(x) + x, giving gradients a multiplicative factor near 1 across the layer. Intuition: a bypass lane that keeps the λᵏ chain from collapsing. Example: the trick behind 100+ layer networks. Related: vanishing gradient, chain rule. In practice/ML: the architectural answer to Unit 6's exponent law.
